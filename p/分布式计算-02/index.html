Ray基本操作流程

Ray 集群的启动与关闭

这是使用 Ray 的第一步，用于初始化分布式环境或关闭已有的集群连接。

  • ray.init()：启动 Ray 集群。在 Jupyter Notebook 或脚本开头调用，初始化分布式运行时环境。
  • ray.shutdown()：关闭 Ray 集群。释放资源，通常在程序结束时调用。

2
3

import ray
ray.init()  # num_cpus可设定启用cpu核数
ray.shutdown()

异步执行

Ray 的核心特性之一是异步非阻塞执行，这使得主程序无需等待耗时任务完成即可继续运行。

  • @ray.remote：装饰器，将普通的 Python 函数转换为远程函数（即 Ray 任务）。
  • .remote()：调用该方法会立即返回一个 ObjectRef（对象引用/取件码），而不会等待函数实际执行完毕。主程序会立刻继续执行下一行代码。

import time

# 定义一个远程任务
@ray.remote
def task_sleep():
    time.sleep(5)
    return "Task Done"

# 异步提交任务
# 代码会瞬间执行到这里，不会卡住等待5秒
task_ref = task_sleep.remote()
print("任务已提交，主程序继续运行...")

同步获取

虽然任务是异步执行的，但在需要使用结果时，必须通过同步阻塞的方式获取。

  • ray.get()：这是一个同步阻塞操作。
    • 如果任务已完成，立即返回结果。
    • 如果任务未完成，主程序会在这里卡住（阻塞），直到结果计算完成并返回。
    • 注意：如果在 .remote() 后立刻接 ray.get()，程序可能会退化为串行计算，失去并行意义。
1
2
3
4

# 获取结果（阻塞操作）
# 如果上面的任务还没睡完5秒，这里就会卡住等待
result = ray.get(task_ref)
print(result)  # 输出: Task Done

共享内存与零拷贝

为了解决大数据在节点间传输占用带宽的问题，Ray 提供了共享内存机制。

  • ray.put()：将大对象（如大型矩阵、数据集）放入分布式共享内存（Object Store）中。
  • ObjectRef 传递：传递 ray.put() 返回的引用 ID，而不是直接传递大数据本身。
  • 零拷贝：如果多个核心在同一物理节点上，它们可以直接读取同一块内存地址，无需复制数据，极大提升效率。

import numpy as np

# 假设有一个巨大的矩阵
large_matrix = np.random.rand(10000, 10000)

# 将大矩阵放入共享内存，返回引用ID
matrix_ref = ray.put(large_matrix)

# 定义一个使用该矩阵的任务
@ray.remote
def process_matrix(matrix_id):
    # 任务内部通过 ray.get 获取数据
    # 如果在同一节点，这是零拷贝读取
    data = ray.get(matrix_id)
    return data.sum()

# 提交任务，传递的是引用ID（很小），而不是巨大的矩阵
result_ref = process_matrix.remote(matrix_ref)
result = ray.get(result_ref)

Map-Reduce思想

利用上述特性可以实现经典的 Map-Reduce 模式：

  1. Map：通过循环调用 .remote() 分发大量子任务。
  2. Barrier：通过 ray.get(list_of_refs) 等待所有任务完成。
  3. Reduce：在主程序中汇总所有结果（如求平均值）。
